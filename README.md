# Greender Trainer — этап 1

Первая версия серверной основы существующего Telegram Mini App. Это **не развёрнутая production-система**: запуск требует вашего проекта Supabase, Vercel и Telegram-бота.

## Реализовано

- Telegram Mini App: серверная проверка `initData` и его давности, подписанная HttpOnly-сессия на 12 часов. Пароль удалён.
- Роли: владелец (из переменной окружения), тренер (назначен в команду), ученик.
- Клубы и команды. Один ученик состоит только в одной команде; самостоятельной смены нет.
- Панель владельца: создание клубов, личные приглашения будущих тренеров, назначение тренера из списка зарегистрированных людей, включение/отключение клубов и команд, срок доступа клуба, блокировка пользователей.
- Приглашение не выдаёт права: получатель сначала подтверждает свой аккаунт Telegram, после чего владелец выбирает его из списка. Сообщения об успехе и ошибках показаны рядом с формами.
- Панель тренера: собственные команды, ссылки-приглашения, заявки, список учеников.
- Бот: `/start`, приглашения, уведомление тренера, кнопки принятия/отклонения.
- Решение заявки проверяется в транзакции. Тренер не может одобрять чужие заявки. Блокировки и сроки проверяются сервером.
- Доступ к исходному коду тренажёров выдаёт `/api/trainer` только одобренным пользователям с действующим доступом.
- Старые тренажёры и обучение сохранены. Исправлен подсчёт правильных раздач в «Победителе».

## Пока НЕ реализовано

Рейтинг и запись результатов в базу, история тренировок, сохранение учебного прогресса, редактор видео/теории, лимит двух попыток теста, выдача дополнительных попыток, экзамен и автоматические условия допуска. Старые учебные экраны работают по прежним правилам. Перенос учеников, замена/снятие тренера и управление отдельными клубными материалами также следующие этапы. Удаление данных намеренно не добавлено: на старте безопаснее отключить доступ.

Это не DRM: авторизованный пользователь может сохранить полученные материалы; уже открытый тренажёр не останавливается мгновенно после блокировки. Новые серверные обращения будут запрещены. Серверная запись результатов с повторной проверкой доступа появится на следующем этапе.

## 1. Supabase

1. Создайте проект Supabase и дождитесь готовности базы.
2. В SQL Editor выполните **один раз** файл `supabase/001_initial.sql` целиком. Если он вернул ошибку, исправьте её до продолжения; файл выполняется одной транзакцией.
3. Сохраните Project URL и серверный Secret key (`sb_secret_...`) из Settings → API Keys. Legacy `service_role` тоже поддерживается, но для нового проекта предпочтителен Secret key.
4. Этот ключ НЕЛЬЗЯ помещать в HTML/JS, GitHub или переменные с `NEXT_PUBLIC_`/`VITE_`. Он существует только в серверных переменных окружения Vercel.

Таблицы закрыты для `anon` и `authenticated`; обращения идут через наш API с серверным ключом. Не выключайте RLS. Supabase Auth для Telegram здесь не используется — аккаунт подтверждает сервер приложения.

## 2. Бот и ID владельца

Используйте существующего бота или создайте нового через настоящий `@BotFather`. Токен держите только в настройках и локальном `.env`, не в чате и не в репозитории.

Нужен ваш **числовой Telegram ID**, не username и не ID бота. Для нового бота без webhook:

1. Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN`.
2. Напишите вашему боту `/start`.
3. Выполните `node --env-file=.env scripts/find-telegram-id.cjs` на своём компьютере с Node.js 22+.
4. Найдите себя по имени/username в выводе и внесите свой `id` в `OWNER_TELEGRAM_ID`.

Если бот уже обслуживается другим приложением/webhook, сначала выясните, можно ли его переключать. Не удаляйте работающий webhook автоматически. Альтернатива — отдельный тестовый бот.

## 3. Vercel

Сохраните резервную копию и разместите файлы в отдельной ветке репозитория. В этой версии `script.js` удалён: вместо него `platform.js` и закрытый `server/trainer-source.txt`. **Не оставляйте старый публичный script.js в новом деплое.** Существующую папку `images/cards` сохраните.

Настройки Vercel: Framework Preset **Other**, без команды сборки, без Output Directory. Поддерживаемый Node.js 22/24. Это обычный статический сайт с функциями `/api/*.js`.

В Project Settings → Environment Variables добавьте значения из `.env.example`:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен вашего бота |
| `BOT_USERNAME` | Username бота без `@` |
| `OWNER_TELEGRAM_ID` | Ваш числовой Telegram ID |
| `APP_URL` | Основной HTTPS-адрес Vercel, например `https://your-project.vercel.app` |
| `SUPABASE_URL` | URL проекта Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ Supabase |
| `SESSION_SECRET` | Случайная строка минимум 32 символа |
| `TELEGRAM_WEBHOOK_SECRET` | Отдельная случайная строка минимум 32 символа; латиница, цифры, `_`, `-` |

Для генерации **каждого** из двух разных секретов выполните локально:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

После добавления переменных выполните Redeploy. `APP_URL` должен точно соответствовать адресу приложения, который открывает бот. Preview-домены по умолчанию не разрешены для запросов записи. В `vercel.json` явные правила `routes` блокируют прямые адреса `/server/*`, `/supabase/*`, `/tests/*`, `/scripts/*` до обработки файлов. Обычные `rewrites` не обеспечивали блокировку существующих статических файлов на Vercel.

## 4. Подключение бота

После успешного деплоя заполните локальный `.env` теми же значениями и выполните:

```sh
node --env-file=.env scripts/setup-bot.cjs
```

Команда проверяет бота, устанавливает webhook `/api/telegram` с секретом и кнопку меню «Обучение». Токен не выводится. Команда меняет текущий webhook бота — запускайте только когда готовы переключить его на это приложение.

Не коммитьте `.env`. Если секрет случайно опубликован, отзовите/замените его, а не просто удалите файл.

## 5. Первый проход

1. Владелец открывает своего бота → `/start` → «Открыть Greender Trainer».
2. Нажимает «Моя команда» → создаёт клуб.
3. Будущий тренер сначала открывает бота и нажимает Start. Владелец вводит настоящий числовой ID человека в форму «Пригласить будущего тренера» и отправляет приглашение. Бот не может первым написать тому, кто его не запускал или заблокировал.
4. Получатель нажимает «Зарегистрироваться» в сообщении бота. После Telegram-входа профиль появляется в базе, но доступ к тренажёрам ещё не выдан. Владелец нажимает «Обновить данные», выбирает человека по имени/username/ID, клуб и название команды, затем «Создать команду и назначить». Самого владельца, заблокированных пользователей и действующих учеников список назначения исключает. После назначения тренеру отправляется уведомление.
5. Тренер повторно открывает приложение → «Моя команда» → копирует ссылку приглашения ученикам.
6. Ученик открывает ссылку. Бот сохраняет заявку и уведомляет тренера.
7. Тренер принимает заявку в сообщении бота или панели.
8. Ученик обновляет данные или повторно открывает приложение. Тренажёры доступны.

Срок доступа задаётся **на клуб**, не на отдельную команду. Пустая дата означает отсутствие ограничения. Выбранная дата включительна до конца дня UTC (в интерфейсе это подписано). Отдельную модель продаж можно добавить позже. Локальная `.env` не загружается в Vercel автоматически.

## Проверки

```sh
npm install
npm test
npm run test:db
npm start
# в другом терминале, если установлен Chromium:
CHROMIUM_PATH=/path/to/chromium npm run test:ui
```

`npm test`: подписи Telegram, сроки входа и сессии, подмена/повтор параметров, серверные ограничения ролей, запрет доступа к коду до одобрения и при отключении клуба, webhook secret.

`test:db`: схема и функции на встроенном PostgreSQL (PGlite), одобрение, запрет чужих заявок, повторов, нескольких команд, блокировки и RLS. Это не подключение к живому Supabase.

`test:ui`: локальный Chromium, мобильный размер экрана, панели владельца/тренера/ожидающего ученика, сохранность тренажёров и исправленный счёт. Данные API и Telegram в этом тесте подставные.

Результат проверок при подготовке: 27 Node-проверок, 18 PostgreSQL-проверок, 20 UI-проверок. Живой Telegram, Vercel и настоящий Supabase ещё не проверены.

## Перед платным запуском

Проверьте весь сценарий на отдельном боте и тестовых аккаунтах. Проверьте, что `/server/trainer-source.txt` недоступен напрямую, а `/api/trainer` без сессии возвращает 401. Отключите публичные старые деплои с прежним паролем. Настройте резервные копии и мониторинг. До нагрузки на сотни участников нужны постраничная загрузка панелей, ограничения частоты запросов и дополнительные операционные проверки. Политика хранения персональных данных и коммерческие договорённости оформляются отдельно.

### Приглашения в тестовой версии

Регистрация и назначение тренера работают через личное приглашение без переключения глобального webhook. Пока webhook не подключён к новой версии, ссылки учеников вида `?start=...` ещё не проверены в полном живом сценарии — это следующий этап. Само приглашение тренера не создаёт профиль: его создаёт настоящий подтверждённый Telegram-вход получателя. Для теста нужен другой реальный аккаунт.
