# Greender Trainer — этап 1

Первая версия серверной основы существующего Telegram Mini App. Это **не развёрнутая production-система**: запуск требует вашего проекта Supabase, Vercel и Telegram-бота.

## Реализовано

- Telegram Mini App: серверная проверка `initData` и его давности, подписанная HttpOnly-сессия на 12 часов. Пароль удалён.
- Роли: владелец (из переменной окружения), тренер (назначен в команду), ученик.
- Клубы и команды. Один ученик состоит только в одной команде; самостоятельной смены нет.
- Панель владельца: создание клубов, личные приглашения будущих тренеров, назначение тренера из списка зарегистрированных людей, включение/отключение клубов и команд, срок доступа клуба, блокировка пользователей.
- Приглашение не выдаёт права: получатель сначала подтверждает свой аккаунт Telegram, после чего владелец выбирает его из списка. Сообщения об успехе и ошибках показаны рядом с формами.
- Панель тренера: собственные команды, ссылки-приглашения, заявки, список учеников.
- Бот: `/start`, приглашения, уведомление тренера, кнопки принятия/отклонения.
- Решение заявки проверяется в транзакции. Тренер не может одобрять чужие заявки. Блокировки и сроки проверяются сервером.
- Доступ к исходному коду тренажёров выдаёт `/api/trainer` только одобренным пользователям с действующим доступом.
- Старые тренажёры и обучение сохранены. Исправлен подсчёт правильных раздач в «Победителе».

## Пока НЕ реализовано

Рейтинг и запись результатов в базу, история тренировок, сохранение учебного прогресса, редактор видео/теории, лимит двух попыток теста, выдача дополнительных попыток, экзамен и автоматические условия допуска. Старые учебные экраны работают по прежним правилам. Перенос учеников владельцем, замена/снятие тренера и управление отдельными клубными материалами также следующие этапы. Удаление данных намеренно не добавлено: на старте безопаснее отключить доступ.

Это не DRM: авторизованный пользователь может сохранить полученные материалы; уже открытый тренажёр не останавливается мгновенно после блокировки. Новые серверные обращения будут запрещены. Серверная запись результатов с повторной проверкой доступа появится на следующем этапе.

## 1. Supabase

1. Создайте проект Supabase и дождитесь готовности базы.
2. В SQL Editor выполните **один раз** `supabase/001_initial.sql`, затем `supabase/002_member_management.sql` целиком. Для уже настроенной базы выполняйте только новую миграцию 002. Если он вернул ошибку, исправьте её до продолжения; файл выполняется одной транзакцией.
3. Сохраните Project URL и серверный Secret key (`sb_secret_...`) из Settings → API Keys. Legacy `service_role` тоже поддерживается, но для нового проекта предпочтителен Secret key.
4. Этот ключ НЕЛЬЗЯ помещать в HTML/JS, GitHub или переменные с `NEXT_PUBLIC_`/`VITE_`. Он существует только в серверных переменных окружения Vercel.

Таблицы закрыты для `anon` и `authenticated`; обращения идут через наш API с серверным ключом. Не выключайте RLS. Supabase Auth для Telegram здесь не используется — аккаунт подтверждает сервер приложения.

## 2. Бот и ID владельца

Используйте существующего бота или создайте нового через настоящий `@BotFather`. Токен держите только в настройках и локальном `.env`, не в чате и не в репозитории.

Нужен ваш **числовой Telegram ID**, не username и не ID бота. Для нового бота без webhook:

1. Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN`.
2. Напишите вашему боту `/start`.
3. Выполните `node --env-file=.env scripts/find-telegram-id.cjs` на своём компьютере с Node.js 22+.
4. Найдите себя по имени/username в выводе и внесите свой `id` в `OWNER_TELEGRAM_ID`.

Если бот уже обслуживается другим приложением/webhook, сначала выясните, можно ли его переключать. Не удаляйте работающий webhook автоматически. Альтернатива — отдельный тестовый бот.

## 3. Vercel

Сохраните резервную копию и разместите файлы в отдельной ветке репозитория. В этой версии `script.js` удалён: вместо него `platform.js` и закрытый `server/trainer-source.txt`. **Не оставляйте старый публичный script.js в новом деплое.** Существующую папку `images/cards` сохраните.

Настройки Vercel: Framework Preset **Other**, без команды сборки, без Output Directory. Поддерживаемый Node.js 22/24. Это обычный статический сайт с функциями `/api/*.js`.

В Project Settings → Environment Variables добавьте значения из `.env.example`:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен вашего бота |
| `BOT_USERNAME` | Username бота без `@` |
| `OWNER_TELEGRAM_ID` | Ваш числовой Telegram ID |
| `APP_URL` | Основной HTTPS-адрес Vercel, например `https://your-project.vercel.app` |
| `SUPABASE_URL` | URL проекта Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ Supabase |
| `SESSION_SECRET` | Случайная строка минимум 32 символа |
| `TELEGRAM_WEBHOOK_SECRET` | Отдельная случайная строка минимум 32 символа; латиница, цифры, `_`, `-` |

Для генерации **каждого** из двух разных секретов выполните локально:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

После добавления переменных выполните Redeploy. `APP_URL` должен точно соответствовать адресу приложения, который открывает бот. Preview-домены по умолчанию не разрешены для запросов записи. В `vercel.json` явные правила `routes` блокируют прямые адреса `/server/*`, `/supabase/*`, `/tests/*`, `/scripts/*` до обработки файлов. Обычные `rewrites` не обеспечивали блокировку существующих статических файлов на Vercel.

## 4. Подключение бота

После успешного деплоя заполните локальный `.env` теми же значениями и выполните:

```sh
node --env-file=.env scripts/setup-bot.cjs
```

Команда проверяет бота, устанавливает webhook `/api/telegram` с секретом и кнопку меню «Обучение». Токен не выводится. Команда меняет текущий webhook бота — запускайте только когда готовы переключить его на это приложение.

Не коммитьте `.env`. Если секрет случайно опубликован, отзовите/замените его, а не просто удалите файл.

## 5. Первый проход

1. Владелец открывает своего бота → `/start` → «Открыть Greender Trainer».
2. Нажимает «Моя команда» → создаёт клуб.
3. Будущий тренер сначала открывает бота и нажимает Start. Владелец вводит настоящий числовой ID человека в форму «Пригласить будущего тренера» и отправляет приглашение. Бот не может первым написать тому, кто его не запускал или заблокировал.
4. Получатель нажимает «Зарегистрироваться» в сообщении бота. После Telegram-входа профиль появляется в базе, но доступ к тренажёрам ещё не выдан. Владелец нажимает «Обновить данные», выбирает человека по имени/username/ID, клуб и название команды, затем «Создать команду и назначить». Самого владельца, заблокированных пользователей и действующих учеников список назначения исключает. После назначения тренеру отправляется уведомление.
5. Тренер повторно открывает приложение → «Моя команда» → копирует ссылку приглашения ученикам.
6. Ученик открывает ссылку. Бот сохраняет заявку и уведомляет тренера.
7. Тренер принимает заявку в сообщении бота или панели.
8. Ученик обновляет данные или повторно открывает приложение. Тренажёры доступны.

Срок доступа задаётся **на клуб**, не на отдельную команду. Пустая дата означает отсутствие ограничения. Выбранная дата включительна до конца дня UTC (в интерфейсе это подписано). Отдельную модель продаж можно добавить позже. Локальная `.env` не загружается в Vercel автоматически.

## Проверки

```sh
npm install
npm test
npm run test:db
npm start
# в другом терминале, если установлен Chromium:
CHROMIUM_PATH=/path/to/chromium npm run test:ui
```

`npm test`: подписи Telegram, сроки входа и сессии, подмена/повтор параметров, серверные ограничения ролей, запрет доступа к коду до одобрения и при отключении клуба, webhook secret.

`test:db`: схема и функции на встроенном PostgreSQL (PGlite), одобрение, запрет чужих заявок, повторов, нескольких команд, блокировки и RLS. Это не подключение к живому Supabase.

`test:ui`: локальный Chromium, мобильный размер экрана, панели владельца/тренера/ожидающего ученика, сохранность тренажёров и исправленный счёт. Данные API и Telegram в этом тесте подставные.

Регрессионные проверки: 32 Node-проверки, 28 проверок базовой схемы, 38 UI-проверок и 25 проверок загрузки. Обучение дополнительно покрыто 30 PostgreSQL-проверками и 23 браузерными проверками. Автотесты используют изолированные данные, не записывают учебные результаты в живой Supabase. Вступление реального ученика через бота ранее проверено владельцем; учебный сценарий после обновления нужно проверить реальными аккаунтами.

## Перед платным запуском

Проверьте весь сценарий на отдельном боте и тестовых аккаунтах. Проверьте, что `/server/trainer-source.txt` недоступен напрямую, а `/api/trainer` без сессии возвращает 401. Отключите публичные старые деплои с прежним паролем. Настройте резервные копии и мониторинг. До нагрузки на сотни участников нужны постраничная загрузка панелей, ограничения частоты запросов и дополнительные операционные проверки. Политика хранения персональных данных и коммерческие договорённости оформляются отдельно.

### Приглашения в тестовой версии

Регистрация и назначение тренера работают через личное приглашение. Для подключения заявок учеников предусмотрен временный preview-only endpoint `POST /api/setup-bot-test`: действия status/connect требуют HMAC с отдельным назначением и сроком не более пяти минут. Подключение меняет глобальный webhook и меню бота; требует разрешения владельца. Очередь Telegram не сбрасывается. Endpoint не выдаёт сессию, роли или секреты. Путь ученика по `?start=...` проверяется реальными аккаунтами после подключения. Само приглашение тренера не создаёт профиль: его создаёт настоящий подтверждённый Telegram-вход получателя. Для теста нужен другой реальный аккаунт.


## Панель управления: клуб → команда → ученик

Владелец открывает «Управление»: клубы, заявки, участники с поиском и управление общими учебными материалами. Формы создания клуба, команды и приглашения тренера вынесены на отдельные экраны. Внутри клуба — команды с именами тренеров; в команде — ученики, заявки и приглашение.

Карточка ученика разделена на «Обучение», «Тренажёры», «Доступ». Обучение показывает сохранённые уроки и отправленные тесты. Тренажёры и экзамен пока остаются явно подписанными заглушками без фиктивных результатов. Дата вступления и последний вход/сообщение берутся из реальных данных. Последний вход — не длительность занятия и не полная статистика активности.

Тренер и владелец могут приостановить/возобновить доступ ученика и убрать его из команды с подтверждением. Удаляется только membership: аккаунт, прежние заявки и аудит остаются. Можно вступить заново по ссылке с новым одобрением. Только владелец блокирует/разблокирует аккаунт во всей платформе. При снятии блокировки отдельно проверяются права команды и клуба. Операции с учениками выполняются транзакционной функцией `manage_member`, которая проверяет реального актёра и принадлежность команды. Существующие memberships миграция сохраняет, выставляя `enabled=true`.


## Состояния загрузки и восстановление

Первый вход показывает скелетоны и проверку Telegram, затем загрузку тренажёров. При обновлении панели уже загруженные карточки остаются на экране. Активная кнопка показывает ход операции; кнопки и поля временно недоступны для повторной отправки. Через 8 секунд появляется подсказка о медленном сервере; API-запрос прерывается через 30 секунд, загрузка тренажёров — через 25 секунд.

Ошибки входа и чтения позволяют повторить безопасный запрос. После ошибки изменения данных предлагается «Проверить состояние», а не автоматическая повторная запись: сервер мог сохранить изменение до потери ответа. Черновики форм, поиск и открытые настройки сохраняются при обновлении панели. Это не офлайн-хранилище: после полного закрытия приложения несохранённые черновики не гарантируются. Лимит ожидания в браузере не откатывает уже начавшуюся серверную операцию.

`npm run test:loading`: 25 браузерных проверок медленного ответа, сетевой ошибки, безопасного повтора, отсутствия дублей, сохранения полей, таймаута, повторной загрузки тренажёров и reduced motion. Скелетоны входа анимируются; статические заглушки будущей статистики не анимируются и не выдают себя за загружаемые результаты.


## Обучение: уроки, попытки и прогресс

Аддитивная миграция `supabase/003_learning.sql` переносит 4 раздела, 53 урока и 52 вопроса из исходного тренажёра, не меняя клубы, команды и участников. Учебные таблицы закрыты RLS, доступ осуществляется только через серверный API с подтверждённой сессией Telegram.

«Обучение» в главном меню открывает каталог. В уроке — необязательное видео, теория и отметка «Ознакомился с уроком», доступная при прокрутке к концу материала. Отметка сохраняется на сервере; это не доказательство просмотра видео. Пока видео не добавлены, уроки доступны без них. YouTube встраивается через youtube-nocookie, HTTPS MP4/WebM открываются в плеере, остальные HTTPS-ссылки — на внешней площадке. Доступ по ссылке не является защитой видео от распространения.

Тест открывается после всех уроков раздела. Для сдачи нужны 100% правильных ответов. Всего две отправленные попытки: открытие, выход и возврат в незавершённый тест попытку не списывают. Черновик ответов сохраняется в localStorage текущего браузера. Вопросы перемешиваются при создании попытки, результат вычисляет сервер по снимку вопросов. Повторная отправка того же attemptId возвращает прежний результат без дополнительного списания. При потере ответа «Проверить состояние» загружает сохранённый результат.

Тренер видит только учеников своих команд: пройденные уроки, число отправленных тестов, последний результат и остаток попыток. После исчерпания попыток тренер или владелец может выдать +1 попытку. Запрос выдачи защищён от повторов; обычный пользователь не может выдать попытку самому себе.

Владелец: «Управление → Обучение → раздел → Редактировать». Можно изменить название урока, теорию и ссылку на видео; изменения общие для всех клубов, текущий прогресс не сбрасывается. После миграции 004 разделы, уроки, вопросы и клубный доступ редактируются через интерфейс (описание ниже). В исходных материалах есть процедуры конкретного клуба: перед коммерческим запуском их нужно согласовать с тренерами.

```sh
npm run test:learning:db
# при запущенном npm start и установленном Chromium:
npm run test:learning:ui
```

Статистика тренажёров, рейтинг и итоговый экзамен — следующие этапы. Редактор клубных блоков добавлен миграцией 004.


## Полный редактор материалов (миграция 004)

Владелец открывает «Управление → Обучение». Можно создать раздел с названием и описанием, выбрать общую доступность или один клуб, добавить уроки и вопросы теста. Тренеры и ученики не имеют доступа к редактору или ключам ответов через учебный API. Клубная видимость проверяется сервером не только при загрузке, но и при отметке урока и начале теста.

Новый материал создаётся как черновик. Урок: название, HTTPS-видео (необязательно), теория. Вопрос: привязка к уроку, текст, 2–6 неповторяющихся вариантов и один правильный; до 100 опубликованных вопросов на раздел. Сначала сохраните форму, затем отдельно нажмите «Опубликовать». Для публикации раздела нужны хотя бы один опубликованный урок и вопрос к опубликованному уроку. Скрытый или архивный родитель скрывает вложенные материалы независимо от их собственной публикации. Если все вопросы скрыты, существующий раздел можно читать, но новый тест недоступен.

Стрелки ↑/↓ меняют порядок разделов, уроков и списка вопросов в редакторе. В самом тесте порядок вопросов по-прежнему перемешивается. Перенос уже созданных уроков или вопросов в другой раздел пока не поддерживается.

«Скрыть от учеников» возвращает материал в черновики. «В архив» требует подтверждения, убирает материал из текущего обучения и сохраняет историю. «Показать архив» раскрывает в списках также архивные материалы. Восстановление возвращает материал в черновики, не публикует автоматически. Архив раздела не меняет собственные статусы вложенных уроков — после восстановления и публикации раздела они снова подчиняются своим статусам.

Полное удаление доступно только для никогда не публиковавшихся черновиков без истории. При удалении раздела/урока удаляются также его неиспользованные вложенные черновики; если хотя бы один вложенный материал публиковался или есть прогресс/попытки/выдачи попыток, сервер запрещает удаление и предлагает архив. Подтверждение предупреждает о необратимости.

Новые уроки не сбрасывают старую сдачу раздела: они показываются непройденными. Изменения вопросов влияют на новые попытки; начатая попытка хранит снимок вопроса и правильного ответа. Архивирование не переписывает оценку и не удаляет результаты; в текущей сводке отображаются только текущие видимые разделы и уроки, история остаётся в базе. Автоматическая повторная аттестация после обновления материалов не вводится.

Учебные данные и настройки клубов сохраняются миграцией; никаких демонстрационных результатов в живой Supabase не добавляется.

Проверки редактора:
```sh
npm test
npm run test:editor:db
# с запущенным npm start и установленным Chromium:
npm run test:editor:ui
```
